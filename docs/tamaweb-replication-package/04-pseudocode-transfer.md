# 04-pseudocode-transfer.md

## 1. 处理结论

用户本轮没有指定需要搬取的伪代码位置。因此：

- 不直接复用 Tamaweb 源码。
- 不搬运任何原始函数体、表达、命名结构或数值表。
- 只抽象行为规格。
- 目标实现按 clean-room 重新设计。

## 4. 无指定伪代码的处理方式

由于没有指定文件、函数或行号，本交付不生成任何“改写后伪代码”条目。目标项目的算法设计只在 `03-feature-specs.md` 和 `05-target-architecture.md` 中以行为规格、模块职责、输入输出和验收标准描述。

如后续需要处理指定伪代码，必须单独新增条目，至少包含：

- 来源文件和行号 / 函数。
- 原始用途。
- 抽象行为。
- 输入和输出。
- 边界条件。
- 是否允许直接复用。
- 推荐处理方式。
- 改写后伪代码。
- 目标实现位置。
- 测试建议。
- 合规说明。

## 5. 归因要求

如果目标项目文档或 README 提到参考来源，应使用这种措辞：

> Gameplay behavior was analyzed from the public Tamaweb repository for clean-room specification purposes. No Tamaweb source code, assets, branding, text, data tables, endpoints, or save formats are copied.

中文：

> 本项目曾参考公开 Tamaweb 仓库进行行为规格分析。未复制 Tamaweb 源码、素材、品牌、文案、数据表、接口 endpoint 或存档格式。
