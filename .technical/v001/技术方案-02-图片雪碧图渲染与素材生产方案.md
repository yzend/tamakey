# 技术方案-02-图片雪碧图渲染与素材生产方案

> 功能定位: 将当前 PixiJS `Graphics` 手绘宠物和场景逐步改造为图片雪碧图渲染，并建立可复用的 AI 生图、裁图、入库素材流程
> 模块归属: L3 渲染层 - PixiJS Renderer / Art Asset Pipeline
> 关联模块: PixiStage, PixiGameRenderer, PetSpriteRenderer, RoomRenderer, ObjectRenderer, assetManifest, public/assets
> 创建日期: 2026-05-08
> 状态: 方案设计

## 1. 目标与结论

| 项         | 结论                                                                    |
| ---------- | ----------------------------------------------------------------------- |
| 渲染方案   | 从 `Graphics.rect()` 手绘切换为 `Texture + Sprite / AnimatedSprite`     |
| 素材组织   | 按状态生成原始大图，裁切成统一 64x64 帧，再拼成雪碧图                   |
| 主角方向   | 以“乐乐的托马猴子”为第一套原创宠物资产，不直接复刻参考图                |
| 当前分辨率 | Pixi 内部画布维持 `160x144`，角色帧采用 `64x64`                         |
| 雪碧图规格 | 单状态一张横向 spritesheet，例如 `monkey-idle.png = 4 * 64 x 64`        |
| Metadata   | 每个宠物一份 JSON，描述状态、帧数、fps、循环、锚点、偏移                |
| 动画 key   | Runtime 以当前 `AnimationName` 为主，manifest 允许 alias 到素材文件     |
| 资产加载   | 保留 `assetManifest.ts` 作为运行时入口，新增 JSON manifest 作为美术数据 |
| 坐标规范   | 统一采用“屏幕坐标 + 角色脚底 baseline + manifest offset”                |
| V1 不做    | 暂不接骨骼动画、Spine、复杂换装、逐像素碰撞、动态光影                   |
| 生成策略   | 先生成状态组原图，再脚本裁切和校验；不手动逐帧切图                      |

## 2. 当前渲染现状

当前 Pixi 画布配置：

```txt
width: 160
height: 144
resolution: 1
autoDensity: false
antialias: false
```

CSS 显示层通过 `image-rendering: pixelated` 放大，因此 64x64 角色帧在桌面端约可显示到 180px 左右，像素边缘不会被平滑。

注意：CSS 的 `image-rendering: pixelated` 只保证 canvas 作为 DOM 元素被放大时不模糊；Pixi 内部 Sprite 纹理采样仍需要在 Pixi 侧单独设置 nearest，并避免非整数坐标、非整数缩放和旋转。

当前渲染分层：

```txt
PixiGameRenderer
  |
  +-- roomLayer      RoomRenderer        当前用 Graphics 画背景
  +-- objectLayer    ObjectRenderer      当前用 Graphics 画便便/家具/活动物件
  +-- petLayer       PetSpriteRenderer   当前用 Graphics 画宠物
  +-- effectLayer    EffectRenderer      当前用 Graphics 画粒子
  +-- overlayLayer   ScreenOverlay       当前用 Graphics 画遮罩/覆盖
```

目标渲染分层：

```txt
PixiGameRenderer
  |
  +-- roomLayer
  |     +-- background Sprite
  |     +-- scene prop Sprites
  |
  +-- objectLayer
  |     +-- poop Sprite
  |     +-- furniture Sprites
  |     +-- garden Sprites
  |
  +-- petLayer
  |     +-- AnimatedSprite(monkey state)
  |     +-- accessory Sprites
  |
  +-- effectLayer
  |     +-- effect AnimatedSprites
  |
  +-- overlayLayer
        +-- LCD overlay / weather / transition
```

## 3. 资产生产总流程

### 3.1 总流程

```txt
参考图 / 美术方向
  |
  v
为每个状态写生图 prompt
  |
  v
生成状态组原图
  |
  +-- idle_raw.png
  +-- sleep_raw.png
  +-- eat_raw.png
  +-- happy_raw.png
  |
  v
sprite-slicer 脚本处理
  |
  +-- 统一缩放到目标网格
  +-- 每格裁切为 64x64
  +-- 背景去除或统一透明
  +-- 重新拼成横向 spritesheet
  +-- 生成 metadata JSON
  |
  v
人工/脚本 QA
  |
  +-- 检查角色是否一致
  +-- 检查帧边界是否溢出
  +-- 检查透明边和像素清晰度
  +-- 检查动画播放是否跳变
  |
  v
入库 public/assets
```

### 3.2 每个状态一组图

一张原始生成图只表达一个状态，不混合多个状态。

```txt
monkey_idle_raw.png
  frame 0: 站立
  frame 1: 呼吸上浮
  frame 2: 眨眼
  frame 3: 回到站立

monkey_sleep_raw.png
  frame 0: 躺下
  frame 1: 呼吸
  frame 2: Zzz
  frame 3: 呼吸回落
```

裁切后输出：

```txt
public/assets/pets/monkey/monkey-idle.png
  size: 256x64
  frame: 64x64
  frames: 4

public/assets/pets/monkey/monkey-sleep.png
  size: 256x64
  frame: 64x64
  frames: 4
```

### 3.3 原始图生成约束

每个状态 prompt 必须包含：

```txt
同一个原创像素猴子角色
4 帧横向排列
每格同等尺寸
角色居中
不要跨格
不要文字
不要 UI
不要复杂背景
背景纯色，方便去底
像素边缘清晰
有限 LCD 绿黑调色板
```

不建议一次生成“所有状态的大合集”，因为角色一致性、裁切和 QA 都更难控制。

## 4. 雪碧图规格

### 4.1 宠物帧规格

| 项              | 规格                                  |
| --------------- | ------------------------------------- |
| 单帧尺寸        | `64x64`                               |
| 基础 sheet 排布 | 横向排列                              |
| 常用帧数        | 2 / 4 / 6                             |
| 透明边距        | 每帧四周至少 4px                      |
| 角色落点        | 脚底或身体底部对齐到同一 y baseline   |
| 文件格式        | PNG                                   |
| 背景            | 透明                                  |
| 插值            | 禁止平滑，Pixi 侧用 nearest/pixelated |

### 4.2 特殊场景帧规格

64x64 适合猴子本体，不适合完整睡觉插画。复杂状态使用更大场景帧。

| 资产类型     |             推荐尺寸 | 用途                         |
| ------------ | -------------------: | ---------------------------- |
| 普通宠物状态 |              `64x64` | idle, happy, sick, eat, play |
| 大型睡觉场景 | `128x80` 或 `128x96` | 猴子 + 枕头 + 被子 + 玩偶    |
| 整屏插画     |             `160x96` | hatch, dream, special event  |
| 背景         |            `160x144` | home, bedroom, garden 等     |
| UI 图标      |    `16x16` / `24x24` | 菜单、状态、资源             |
| 特效         |    `32x32` / `64x64` | 心心、Zzz、闪光、生病        |

### 4.3 像素清晰度策略

必须同时约束浏览器显示层和 Pixi 内部采样。

| 层级             | 策略                                                               | 说明                                     |
| ---------------- | ------------------------------------------------------------------ | ---------------------------------------- |
| Pixi Application | 继续使用 `antialias: false`, `resolution: 1`, `autoDensity: false` | 保持当前低分辨率游戏画布                 |
| Pixi Texture     | 统一设置 nearest scale mode                                        | 避免 Sprite 在 Pixi 内部缩放时被线性采样 |
| Sprite 坐标      | `x/y/width/height/scale` 使用整数或整数倍                          | 避免亚像素采样造成边缘发虚               |
| Sprite 旋转      | V1 禁止旋转角色和关键像素资产                                      | 旋转会破坏像素网格                       |
| CSS canvas       | 保留 `image-rendering: pixelated`                                  | 保证 160x144 canvas 被 DOM 放大时清晰    |
| QA               | 用 Playwright 截图 + canvas pixel check 验证                       | 检查是否出现模糊边、半透明毛边           |

Pixi v8 接入时需要在 Sprite/Texture 加载层明确实现：

```txt
加载 texture
  |
  +-> 设置 texture.source.scaleMode = nearest
  |
  +-> 创建 Sprite / AnimatedSprite
  |
  +-> 坐标 round 到整数
  |
  +-> 禁止非整数 scale 和 rotation
```

验收方式：

```txt
打开 160x144 Pixi 画布
  |
  +-> 桌面宽度放大到约 470px
  |
  +-> 移动宽度放大到约 340px
  |
  +-> 截图检查角色轮廓像素边
  |
  +-> canvas 像素采样确认非空且边缘无明显灰阶糊边
```

### 5.3 坐标、锚点和 baseline 规范

当前 `PetSpriteRenderer` 使用 `petContainer.x/y` 控制手绘图形位置。改成 Sprite 后统一改为“屏幕坐标 + 脚底 baseline”：

| 资产类型   |                  逻辑尺寸 | 默认屏幕中心点 | baseline y | anchor             | 说明                |
| ---------- | ------------------------: | -------------: | ---------: | ------------------ | ------------------- |
| 普通猴子   |                   `64x64` |    `(80, 112)` |      `112` | `{ x: 0.5, y: 1 }` | 角色脚底贴近地面线  |
| 蛋         | `64x64` 或 `128x64` sheet |    `(80, 106)` |      `106` | `{ x: 0.5, y: 1 }` | 蛋略高于普通角色    |
| 睡觉大场景 |                  `128x80` |    `(80, 116)` |      `116` | `{ x: 0.5, y: 1 }` | 床/被子整体贴近底部 |
| 死亡/倒下  |                   `64x64` |    `(80, 116)` |      `116` | `{ x: 0.5, y: 1 }` | 允许更靠近地面      |

渲染计算：

```txt
screenX = baseCenterX + manifest.offset.x
screenY = baselineY + manifest.offset.y
sprite.anchor = manifest.anchor
sprite.position = round(screenX, screenY)
```

动画位移策略：

| 动画                    | 策略                                                                  |
| ----------------------- | --------------------------------------------------------------------- |
| idle 呼吸               | 优先用帧动画；必要时容器 y 只做整数 `0/-1`                            |
| sick 抖动               | 容器 x 只做整数 `-1/+1`                                               |
| sleep 呼吸              | 优先用睡觉 sheet 帧；不额外做亚像素位移                               |
| one-shot eat/play/clean | 由 `playOnce` 播放对应 sheet，结束后回到 `chooseAnimation(viewModel)` |

状态映射：

```txt
PetStage + PetMood + SleepState + SicknessState
  |
  v
AnimationName
  |
  v
manifest.animations[AnimationName]
  |
  v
Pixi AnimatedSprite
```

### 5.4 资产加载与 assetManifest 迁移

当前 `src/game/rendering/assetManifest.ts` 只预留静态路径，且渲染器还没有真正使用它。V1 改造时不删除它，而是把它升级为运行时统一入口。

目标职责：

| 文件                                    | 角色            | 说明                                          |
| --------------------------------------- | --------------- | --------------------------------------------- |
| `src/game/rendering/assetManifest.ts`   | TypeScript 入口 | 暴露 manifest 路径、默认 fallback、预加载清单 |
| `public/assets/pets/monkey/monkey.json` | 美术 manifest   | 描述猴子动画 sheet                            |
| `public/assets/rooms/*.png`             | 房间背景        | 由 RoomRenderer 加载                          |
| `public/assets/objects/*.png`           | 场景物件        | 由 ObjectRenderer 加载                        |
| `public/assets/effects/*.png`           | 特效 sheet      | 由 EffectRenderer 加载                        |

迁移步骤：

```txt
保留 assetManifest.ts
  |
  +-> 新增 petManifests.monkey = "/assets/pets/monkey/monkey.json"
  |
  +-> 新增 room fallback 路径
  |
  +-> PixiStage 初始化时预加载 P0 manifest
  |
  +-> PetSpriteRenderer 优先读 manifest texture
  |
  +-> 加载失败时回到 createFallbackPet(Graphics)
```

旧路径兼容：

```txt
/assets/pets/egg.png
/assets/pets/baby.png
/assets/pets/child.png
/assets/pets/adult.png
/assets/pets/dead.png
```

这些旧路径不作为新素材规范，但在一版迁移期内保留在 `assetManifest.ts` 的 `legacy` 字段中，避免已有引用或测试 fixture 失效。

### 6.1.1 一次性交互动画映射

当前 `PixiGameRenderer.handleGameEvent()` 只把交互事件交给 `EffectRenderer`，尚未驱动 `PetSpriteRenderer.playOnce()`。接入图片雪碧图时需要补这条链路。

```txt
GameEvent interactionApplied
  |
  +-> PixiGameRenderer.handleGameEvent()
      |
      +-> EffectRenderer.playInteraction()
      |
      +-> PetSpriteRenderer.playOnce(oneShotAnimation)
          |
          +-> 播放完成
              |
              +-> 回到 chooseAnimation(viewModel)
```

| `InteractionType`                           | 一次性动画                           | 资产                                    | 覆盖策略                                                  |
| ------------------------------------------- | ------------------------------------ | --------------------------------------- | --------------------------------------------------------- |
| `feedMeal` / `feedSnack`                    | `pet_eat`                            | `monkey-eat.png`                        | 覆盖当前 mood 动画，播放完成回到基础状态                  |
| `play` / `startMinigame` / `finishMinigame` | `pet_play`                           | `monkey-play.png`                       | P0 可 fallback 到 `monkey-happy.png`                      |
| `clean` / `bath` / `brushTeeth`             | `pet_clean`（新增 alias）            | `monkey-clean.png`                      | 若不扩展 `AnimationName`，作为 renderer 内部 one-shot key |
| `medicine`                                  | `pet_sick` -> recovery effect        | `monkey-sick.png` + `clean-sparkle.png` | 不新增药品专用角色帧                                      |
| `pet` / `praise`                            | `baby_happy/child_happy/adult_happy` | `monkey-happy.png`                      | 临时播放 happy sheet                                      |
| `scold`                                     | `baby_sad/child_sad/adult_sad`       | `monkey-sad.png`                        | 临时播放 sad sheet                                        |

播放优先级：

```txt
one-shot 正在播放
  |
  +-- 新的 one-shot 到来
  |     -> 允许打断，播放最新交互
  |
```

### 7.3.1 花园 ViewModel 扩展边界

当前 Pixi `PetViewModel` 只包含：

```txt

furniture: string[]
```

这不足以表达完整花园地块状态，也不足以表达家具坐标。分阶段处理：

| 阶段 | ViewModel                                        | 支持素材                                    | 限制                            |
| ---- | ------------------------------------------------ | ------------------------------------------- | ------------------------------- |
| P0   | 保持 `gardenReadyCount`                          | `garden-plot-empty.png`, `garden-ready.png` | 只能按 ready 数量绘制粗粒度状态 |
| P1   | 增加 `plots: GardenPlotState[]`                  | seed/sprout/ready/withered                  | 能按地块真实状态绘制            |
| P1   | 增加 `furniturePlacements: FurniturePlacement[]` | bed/lamp/plant/rug 等                       | 能按玩家摆放坐标绘制            |
| P2   | 增加 `garden.animals` 映射                       | helper-bird/garden-cat                      | 能绘制花园动物                  |

P0 渲染规则：

```txt
sceneId = garden
  |
  +-> 3 个固定地块位置
      |
      +-- index < gardenReadyCount -> garden-ready.png
      |
      +-- otherwise -> garden-plot-empty.png
```

P1 渲染规则：

```txt
plot.cropId = null
  -> garden-plot-empty.png

plot.cropId != null && plot.readyAt = null && plot.witheredAt = null
  -> garden-sprout.png

plot.readyAt != null && plot.witheredAt = null
  -> garden-ready.png

plot.witheredAt != null
  -> garden-withered.png
```

### 7.5.1 家具摆放能力边界

当前 `ObjectRenderer` 只能按 `viewModel.furniture` 数组顺序自动摆放：

```txt

```

因此家具素材分两层验收：

| 阶段 | 能力                                    | 验收                           |
| ---- | --------------------------------------- | ------------------------------ |
| P0   | 静态 room 背景里画死少量家具            | 不需要 `furniturePlacements`   |
| P1   | 通过 `furniture: string[]` 顺序绘制     | 只支持固定位置，不支持用户摆放 |
| P2   | 扩展 `PetViewModel.furniturePlacements` | 支持用户摆放坐标、前后层级     |

如果要真正支持家具装修，必须同步修改：

```txt
GameState.world.furniturePlacements
  |
  v
selectPetViewModel()
  |
  v
PetViewModel.furniturePlacements
  |
  v
ObjectRenderer 按 x/y/zIndex 绘制 Sprite
```

## 9. 生图任务拆分

可以用多 agent / 多批次并行生成，但最终必须通过同一套裁图和 QA。

| 任务       | 输入                   | 输出                   | 验收                         |
| ---------- | ---------------------- | ---------------------- | ---------------------------- |
| 角色基准图 | 参考图 + 角色特征描述  | `monkey-reference.png` | 固定角色比例和轮廓           |
| 猴子状态组 | 角色基准 + 状态 prompt | raw 状态组图           | 同角色、同尺寸、不跨格       |
| 背景组     | LCD 风格 + 场景 prompt | room PNG               | 不抢角色视觉中心             |
| 道具组     | 单物件 prompt          | item/object PNG        | 24/32px 清晰可识别           |
| 特效组     | 帧动画 prompt          | effect sheet           | 循环自然、边界不溢出         |
| 裁切 QA    | raw 图 + 参数          | 64x64 sheet + JSON     | 尺寸正确、透明正确、动画不跳 |

## 11. 风险与约束

| 风险                       | 说明                              | 处理                                          |
| -------------------------- | --------------------------------- | --------------------------------------------- |
| AI 多帧角色不一致          | 同一角色在不同帧脸型/耳朵可能漂移 | 先生成角色基准，再逐状态生成；QA 不合格重生成 |
| 裁切后角色跳动             | 每帧主体位置不一致                | 裁图脚本支持 anchor/baseline 校准             |
| 64x64 无法表达复杂场景     | 睡觉图有枕头/被子/玩偶            | 普通状态 64x64，复杂状态用 128x80             |
| 透明边有毛边               | 生图背景不纯或抗锯齿              | 使用纯色背景 + chroma key 去底 + 像素化后处理 |
| 当前代码缺少 Sprite loader | 目前 `Graphics` 是主路径          | 分阶段接入，不一次替换所有 renderer           |
